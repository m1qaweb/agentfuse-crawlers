# P23C1 — Frozen two-round Zyte canary archive evidence gate

**Status:** implemented as an **offline accession tool**. The real P23C
publisher reviews and Zyte canary collection have NOT been performed by this PR.

**Scope:** P23B (merged PR #80) now blocks even one publisher request without
a current exact-source Git-reviewed `single_validation` decision. P23C1
makes the next step auditable: it requires predeclared **18 exact original
P20A source IDs / 36 original round slots**, plus the existing immutable Zyte
Items archive format. No review or job is fabricated.

## First, distinguish what exists from what is still missing

| Evidence | Current repository / P23C1 | Additional human/operator action |
|---|---|---|
| Original 18 IDs + 36 source-round denominator | Frozen and enforced | Do not swap blocked sources |
| P23B source review registry | Loaded and enforced; currently empty | Individually review owners/terms/robots/retention, approve or deny and merge genuine records |
| One-source pinned Zyte job args | Already generated by P20A | Verify exact P23B package in the actual deployed Zyte project, then manually authorize **only permitted** jobs |
| Immutable completed Zyte Items archives | Offline verifier implemented; no real archives included | Archive genuine completed jobs with `scripts.archive_jobs` |
| Distinct round identity/order | Bound to two distinct job IDs and increasing job starts | Run only when legitimately authorized; keep both job exports |
| Full Requests + Logs | **NOT independently inspected** by this tool | Retain and review original Zyte Requests/Logs outside public CI |
| Original publisher HTML | **NOT in a Zyte Items archive** | Collect via already authorized source-specific P22A1 workflow, original bytes and SHA-256 |
| Independent accuracy / permission / publisher proof | **Not asserted** | Two genuine human reviewers and source-specific policy research |
| 460-source diagnostic GO | **NO-GO** | P23C2–P23E evidence and source-specific approval |

The existing `archive_jobs.py` produces deterministic, indexed, compressed
Items with metadata and checksums. It does **not** contain raw original HTML,
the full Zyte Requests export or the full Logs export. An Items archive can
pass a SHA check despite originating from an untrusted/synthetic export;
checksums do not independently authenticate Zyte or publisher origin.

## 1. Obtain BLANK receipt slots (no local checkout needed)

After merge, GitHub → **Actions** → **Prepare Zyte UI preflight (no crawl)** →
**Run workflow** on `main`. Download the no-crawl artifact and find:

- `p23c1-blank/frozen_p20a_plan.json`: identical P20A/P22A1 frozen original
  cohort, with 18 sources, 6 docs/6 pricing/6 changelogs, 36 rounds
- `p23c1-blank/zyte_canary_job_receipts_BLANK.json`: **all 36**
  `zyte_job_id=null`, no publisher permission and no job scheduled
- `p23c1-blank/READ_ME_NO_CRAWL.txt`: private-evidence handling guide

Alternatively, from a reviewed local checkout:

```bash
python -m scripts.p23c1_zyte_canary_archive_gate \
  --prepare --out-dir output/private/p23c1-blank-1
```

The same GitHub artifact includes the original `p20b-preflight/wave_01` and
`wave_02` exact, single-source, two-round manual job plans.

**Do not enter a Zyte job key until you actually have a completed, specifically
authorized real Zyte job with that key.** An empty or denied source is an
explicit held denominator slot, not missing data to replace.

## 2. Genuine source review and deployed package prerequisites

The P23B source-review registry is at
`agentfuse_crawlers/data/validation_access_reviews.json`. A positive
`single_validation` record requires actual publisher ownership, access
terms, robots and private-retention reviews with a human reviewer, source URL,
category, expiry <= 30 days and evidence notes. Follow
`docs/P23B_SINGLE_SOURCE_VALIDATION_ACCESS.md`.

Only merge **genuine human determinations**. The template contains none;
neither this script nor a model can create permission by filling booleans.

Before any live run, independently verify that Zyte's actual deployed
package fingerprint matches the reviewed `main` production fingerprint.
P23C1 can compare an exported Item's claimed deployment digest against the
local installed package; this is NOT remote authentication.

The source must also remain permitted when the first request is made.
Source review expires and per-source source identity can change.

## 3. Manually run permitted canaries, then archive completed jobs

Only after independently confirming publisher access and human operator
budget authorization, choose one originally selected and **permitted**
source. Use EXACT P20A arguments:

```text
cohort                        all
source_ids                    EXACT_SOURCE_ID
collection_mode               validation
expected_manifest_sha256      FROM_FROZEN_PLAN
expected_selection_ids_sha256 FROM_ONE_SOURCE_JOB_ARGS
expected_source_registry_sha256 FROM_FROZEN_PLAN
```

Run two distinct jobs per source without changing their original study
selection; archive **all** metadata, Items, Requests and Logs privately.
Do not bypass 403/429/captcha/robots, follow different-path redirects,
substitute a source or add undisclosed source arguments.

The existing downloader requires credentials ONLY for the private download
step; it never schedules jobs or runs publishers:

```bash
python -m scripts.archive_jobs \
  --job-id EXACT_JOB_ID \
  --out-dir /secure/p23c-zyte-archives
```

This creates a private folder
`/secure/p23c-zyte-archives/jobs/JOB_ID_UNDERSCORED/`
containing `envelope.json`, `index.json` and `items.jsonl.gz`.
Keep originals and complete Requests/Logs separately in secured storage.
**P23C1 does not inspect the additional files; this is still a blocker.**

## 4. Privately audit the 18/36 receipt ledger with ZERO network

Fill ONLY `zyte_job_id` for completed, correctly reviewed jobs in a private
copy of `zyte_canary_job_receipts_BLANK.json`. Preserve every source and
source-round entry in the original order. Two rounds must use different job
IDs with increasing actual start times. Round 2 cannot be supplied while
round 1 is blank. Do not commit this filled ledger or real exports to GitHub.

```bash
python -m scripts.p23c1_zyte_canary_archive_gate \
  --audit \
  --private-receipts /secure/p23c-zyte-canary-receipts_FILLED.json \
  --archive-root /secure/p23c-zyte-archives \
  --out-dir /secure/p23c1-audit-1
```

The script checks that **each** supplied archive:

- passes `archive_jobs.load_archive` checksum, index and gzip validation;
- has **exactly one** source Item and correct spider/category, source ID,
  provider/URL, known job key and complete Zyte scope;
- uses a P20A `cohort=all`, explicitly pinned `source_ids` and
  `collection_mode=validation`, with all three exact manifest/selection/
  source-lifecycle SHA pins;
- has P23B `single_exact_source` scope, no bulk override, unapproved advisor
  status, matching claimed installed package fingerprint, and the same
  exact-source review-registry SHA as the current inspected registry;
- falls within the exact human source review window (the review must already
  predate the archived job, and must still be current to perform this audit);
- does not reuse a job or swap a source, a round, or the original wave;
- does not treat an HTTP 200 Item as independently authenticated publisher
  origin or a correct price, release, or capability fact.

The new-only private output contains
`zyte_canary_36_rounds_NO_GO.json` and `all_36_rounds.csv`. It reports
each held, absent, policy-blocked, failed, or merely observed source-round
without reducing the original denominator.

**Even 36/36 internally consistent completed jobs do not make this a
successful real-world validation.** P23C1 intentionally reports `NO_GO`;
the next phase must check real Requests, Logs, original publisher HTML,
genuine operator review, and independent data-quality labels.

## 5. Verification, constraints and next step

```bash
python -m pytest -q tests/test_p23c1_zyte_canary_archive_gate.py
python -m pytest -q
```

No source permissions, URLs, spiders, schedules, Zyte jobs, user secrets,
original publisher HTML, real human reviews, DB writes, advisor facts or
production runtime crawler package changes are introduced. CI creates
**blank fixtures only**. All positive scenarios in tests use unmistakably
synthetic in-memory policy records and fake archive metadata.

After merging P23C1, the next implementation is **P23C2**: private
cross-check of actual Zyte Requests and Logs against exact claimed
publisher GETs, plus source-owned original HTML accession through P22A1.
Actual publisher approvals and live canaries still require a real human
operator, and all prohibited publishers must remain held.

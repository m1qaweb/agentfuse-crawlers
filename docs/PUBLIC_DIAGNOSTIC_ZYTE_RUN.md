# Run the public-source diagnostic campaign

The project owner requested a practical, bounded public-information crawl
instead of hundreds of individually prepared affirmative internal approvals.
This is an explicit **project-side diagnostic scope**, NOT a publisher grant,
legal clearance, unrestricted redistribution right, or advisor release.

Use the new deployed package, not an older empty-authorization egg.
Run the existing three spiders in sequence. For each one, the three
Dashboard arguments are:

| Name | Value |
|---|---|
| cohort | all |
| confirm_full_inventory | public_diagnostic |
| collection_mode | validation |

Start with official_pricing, then official_documentation, then
official_changelogs. The installed scope starts with 274 exact original
manifest sources: 115 pricing, 123 documentation, 36 changelog. 160 have
successful/recognized missing-file robots observations from actual GitHub
run 45636993742 after exclusions; 114 historically reachable reserves
will be checked by the existing live robots middleware. The scope excludes
prior substantive policy holds, related held groups, unresolved live robots
groups, historical failed/redirected source IDs, quarantines and separate
release-API candidates. This is not an exhaustive individual terms review.
Do not collect content known to be prohibited, and do not use collected
excerpts for redistribution or production recommendations without checking
applicable rights and factual quality.

The package scope expires on 2026-12-25 UTC. Use a current package.
The older confirm_full_inventory=yes behavior and fully reviewed policy
records remain unchanged, including single-source and monitoring gates.
The new option cannot take arbitrary URLs, shards, or silently override a
negative individual review. Actual robots checks, no retry/redirect,
one primary GET per source, group holds, request/runtime caps, exact
identity and immediate systemic stops remain. Three consecutive distinct
group barriers without an intervening healthy primary response cause
global shutdown; the stricter old threshold still applies to old plans.
A healthy response does not clear a publisher hold.

If a publisher group is held, do not retry it or request another related
host/path in a later category. Inspect Items, Requests, Logs and close
reason after each job; carry the exact group IDs (validation_containment_group
where validation_containment_block_reason is nonempty) to later jobs via
the optional public_diagnostic_held_groups comma-separated argument.
This only narrows the scope. Stop the sequence on systemic/integrity errors,
and reconcile incomplete output before proceeding. Independent Dashboard
jobs do not share memory or a trusted cross-job ledger; the operator must
enforce this sequence. The original P25 reviewed-plan launcher/audit remains
strict and is not the launcher for this diagnostic scope.

Export Items, Requests, Logs privately. Distinguish actual primary requests,
HTTP successes, usable facts, and held records. The candidate count is not
a promise of 200 successes. Existing extractions remain unverified; don't
publish a raw copy of publisher pages. No new paid features, API secrets,
deployments, or Zyte jobs are created by this change.
